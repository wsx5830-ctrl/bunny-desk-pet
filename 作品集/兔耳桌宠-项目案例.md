## 一、一句话简介

输入只有一张画师绘制的**单层插画**，通过自动切层算法逆向得到 11 个带枢轴的部件，用"描边拓扑 + 枢轴旋转"替代 Live2D 实现骨骼动画；配合声明式皮肤系统，新增一套皮肤只需一条命令。同一套资产同时驱动**网页版**与 **Windows 桌面端（WPF，零依赖）**。

## 三、背景与约束

- 原始素材是**白底合层图**：没有分层、没有骨骼、没有动画，也没有 Live2D 源文件。
- 不使用 Live2D / Spine：学习与制作成本高，且要求人工分层源文件，无法支撑"持续加新皮肤"的需求。
- 核心矛盾：**要么每加一套皮肤重做一遍动画，要么把"分层"和"动画"都做成可复用的流水线。** 选择了后者。

## 四、技术方案（按数据流）

1. **自动抠图**（cut_bg.py / cut_master.py）
   边缘洪水填充 + alpha 通道检查；关键点：区分"背景白"与"内容白"（短裤、眼睛高光必须保留）。

2. **自动切层**（petsplit.py）—— 项目核心算法
   皮肤、兔耳、短裤全为白色系，颜色聚类失效。改用画师的**描边拓扑**特征：
   暗色描边阈值（V<150）→ 形态学腐蚀切断抗锯齿"桥接"（5 次腐蚀，取前 2 个最大暗色核心，避免眼睛被刘海轮廓吸走）→ `ndimage.label` 连通域 → 距离变换测描边厚度（区分"细描边"与"大面积暗色填充"）→ 最近邻像素按区域归属 → 1–2px 出血 + 0.7px alpha 羽化消除白边。

3. **骨骼与动画**
   每层一个 pivot（耳根 / 眼心 / 腰线），绕 pivot 旋转模拟骨骼；呼吸、眨眼、点头、头发摆动、耳朵摆动多层叠加；皮肤可声明 `anim` 开关（如 `earSway:false`）。

4. **皮肤系统**（ingest_skin.py / build_skins.py / skin.json）
   声明式配置：`canvas / baseline / accent / layers / pivots / anim / quotes`。
   `REQUIRED=["face","body","hair"]` 等校验保证新皮肤不缺件；未独立分层的耳朵自动降级为"耳朵静止"，其余动画保留；通用台词池 + 皮肤专属池合并。

5. **双端运行时**
   - Web：DOM 分层 + CSS/JS 动画（pet-demo-skins.html）
   - Windows：PowerShell 5.1 + WPF 透明置顶窗口（DeskPet.ps1，716 行，零第三方依赖），含重力坠落（2200）、90s 入睡、4.5–9s 主动闲聊、托盘菜单、自建桌面快捷方式。

6. **质量保障**
   jsdom 无头回归测试（tools/test_drag.js）；`-Diagnostics` 自检模式；构建脚本（build_skins.py）做完整性校验。

## 五、难点与修复（面试重点素材）

| # | 问题 | 根因 | 修复 |
|---|---|---|---|
| 1 | 区域粘连、眼睛粘在刘海上 | 抗锯齿像素桥接相邻区域 | 加宽暗色阈值至 V<150 + 5 次腐蚀取核心 |
| 2 | 耳层带灰色阴影条 | 阴影被划入耳层轮廓 | 低饱和灰过滤器清除 |
| 3 | 蓝贝雷帽变透明 | 同一灰影过滤器误杀低饱和大色块 | 过滤条件加约束：厚度<10px 且面积<300px²（一次修复解决两个 bug） |
| 4 | 桌宠只露一角 | 每帧挤压值写入同一 RenderTransform，覆盖 0.34 基础缩放 | 拆两层变换：stage 管基础缩放，petCanvas 管挤压 |
| 5 | 网页拖拽失效 | 气泡节点在切层时被误删、say() 空指针 | DOM 结构调整 + 坐标先存后用 + 空值保护 |
| 6 | 台词复读 | 状态键拼接为字面量 `"$|$state"` | 改为 `"|"+$state` 真正按键取池 |

## 七、简历 bullet（按岗位选一）

- **算法向**：设计"描边拓扑 + 形态学"图像切层算法，将单张插画自动逆向分层为 11 个带枢轴的部件，替代人工分层，支撑 11 套皮肤流水线化接入。

## 八、面试 3 分钟讲述脚本

1. **结果先行（30s）**：把画师的一张合层插画，做成 11 套皮肤可热切换、会说话的桌面宠物，网页版在线可玩，Windows 端解压即用。
